Use this page to find the TypeScript names. For accepted config values,
defaults, results, and use cases, start with the [configuration guide](../configuration/).
The `@vp-tw/dirwell` package root exports the values and types below from `src/index.ts`.
The `@vp-tw/dirwell/theme` subpath exposes the component contracts from
`src/theme-components.ts`, including the generic `ThemeComponent<Props>` type.
The `@vp-tw/dirwell/vite` subpath exports the Vite adapter and its `DirwellViteOptions`
type. `Dirwell(options)` returns one Vite plugin; `Dirwell([options, ...])`
returns a plugin array. See [Vite adapter](../configuration/#vite-adapter).
The command-line interface is described separately under [CLI](../cli/).
Use the [configuration guide](../configuration/) and [theme guide](../themes/)
for behavior and design examples. The code blocks on this page are imported from
TypeScript files checked by the repository tests.

## Run a Node build

Install `@vp-tw/dirwell` in your project and create `build-explorer.mjs`:

```js
import { generateExplorer } from "@vp-tw/dirwell";

await generateExplorer({
  sourceDir: "./downloads",
  outputDir: "./site-downloads",
});
```

Run `node build-explorer.mjs` from the project directory. Await completion before
serving or publishing the output. The generator replaces the output tree after a
successful render; use a dedicated output directory. Use a [build adapter](../build-tools/)
when another tool owns the application output.

The other adapter subpaths export their factory and `DirwellPluginOptions`.
`@vp-tw/dirwell/unplugin` exposes the available factories as named properties.
See [support and compatibility](../support/) before choosing an integration.

## Configure a build

`defineConfig()` preserves the input type and accepts an object or a function
receiving `{ command: "build" | "serve" | "daemon" }`. The function may be
asynchronous. A `dirwell.config.ts` file is discovered from `--cwd`.

| Field        | Accepted input; default and effect                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `root`       | Directory path; `.` for `resolveGenerateOptions()`. The CLI positional directory takes precedence and itself defaults to `.`.        |
| `outDir`     | `dist/` for build; `.dirwell-preview/` for serve and daemon.                                                                         |
| `mode`       | `"ssg"`; `"mpa"` shares runtime assets under `__dirwell/`.                                                                           |
| `mirror`     | `true`; copy source files to the output.                                                                                             |
| `include`    | All source entries; root-relative glob or array of globs. Matching directories include descendants.                                  |
| `exclude`    | No exclusions; root-relative glob or array of globs. Exclusions win over inclusions.                                                 |
| `base`       | `/`; root-relative path or HTTP(S) URL without query or fragment.                                                                    |
| `urls`       | `"relative"`; also accepts `"base"` and `"html-base"`.                                                                               |
| `outputName` | Safe filename or sync/async resolver; `defaultOutputName` uses `_dirwell.html` when an index exists and skips when both names exist. |
| `sort`       | `field`, `nameMode`, `direction`, and `directoriesFirst`; name, natural comparison, ascending, directories first.                    |
| `symlinks`   | `follow`, `boundary`, and `onCycle`; `{ follow: false, boundary: "root", onCycle: "skip" }`.                                         |
| `metadata`   | Shared title/description and image settings; built-in themes supply defaults. See [metadata](../metadata/).                          |
| `theme`      | `defaultTheme`.                                                                                                                      |
| `server`     | Serve/daemon host `127.0.0.1`, port `4173`; `HOST` and `PORT` may override these.                                                    |
| `extends`    | No inherited config; local path or array of local paths.                                                                             |

| Option           | Commands                                | Default or effect                                                      |
| ---------------- | --------------------------------------- | ---------------------------------------------------------------------- |
| `[directory]`    | `build`, `serve`, `dev`, `daemon start` | `.`; positional source directory.                                      |
| `--cwd`          | All commands                            | `.`; config discovery and daemon state directory.                      |
| `--base`         | `build`, `serve`, `dev`, `daemon start` | Config `base`, otherwise `/`.                                          |
| `--mode`         | `build`, `serve`, `dev`, `daemon start` | `ssg` or `mpa`; config or SSG default.                                 |
| `--urls`         | `build`, `serve`, `dev`, `daemon start` | `relative`, `base`, or `html-base`; config or relative default.        |
| `-o`, `--outDir` | `build`, `serve`, `dev`, `daemon start` | Output path; build defaults to `dist/`, server to `.dirwell-preview/`. |
| `--host`         | `serve`, `dev`, `daemon start`          | `HOST`, config, or `127.0.0.1`.                                        |
| `-p`, `--port`   | `serve`, `dev`, `daemon start`          | `PORT`, config, or `4173`.                                             |

`daemon status` and `daemon stop` accept `--cwd`. `daemon` defaults to `start`;
`dev` aliases `serve`, and a bare directory also invokes `serve`. Run
`dirwell <command> --help` for generated help and current flag spelling.

## Opt-in listing publication

`GenerateOptions.listing` and `DirwellConfig.listing` accept a `ListingPlan` or
`ListingPolicy` callback. HTML publication and data transport are independent:

```ts
listing: {
  html: { strategy: "paged", pageSize: 100 },
  data: { strategy: "blocks", blockSize: 200 },
}
```

Use Plain or an independent theme that declares `listing: { pagination: true }`
for paged HTML. Ledger and Crosswave currently reject paged plans because their
existing local search and sorting require complete data. They can publish data
with `html: { strategy: "all" }`. Nothing is published unless listing is enabled;
Plain remains script-free and emits no default metadata images.

`ListingPolicyContext` supplies `directoryPath`, filtered `visibleCount`,
`dataBytes` (the UTF-8 JSON record-array size, excluding manifest/block envelopes),
`mode`, and `supportsPagination`. The synchronous callback runs once per generated
directory. Return a complete plan; `validateListingPlan` rejects invalid strategies
and non-positive or unsafe integer sizes before output replacement. There is no
built-in automatic threshold in this version. A threshold is application policy,
not a universal recommendation.

`projectListingEntry` takes `(entry, context)` and produces a `ListingEntry` using the core's
prepared URL and exit flag. It omits absolute/resolved filesystem paths and private
stat fields. Declared symlink target text is intentionally retained, matching
existing theme and raw-link behavior. Its unavailable flag follows existing core
navigation policy; a cycle is reported independently.

When enabled, `ThemeContext.listing` is a `ListingContext` containing the revision,
manifest URL and `ListingPage`. `directory.entries` contains the current HTML
slice; use `listing.page.total` for directory-wide counts. Emit native anchors for
`previousHref` and `nextHref`, when non-null. Each additional page is published
beside the directory's initial HTML, including in MPA mode; metadata callbacks see
the full directory and core canonical URLs identify the actual page. Local-only
sorting of a slice must not be presented as directory-wide sorting.

The `ListingManifest` uses version 1 and includes a directory, total, sort, revision,
`hrefBase` and block descriptors. Resolve block URLs relative to the manifest URL.
Resolve record URLs against `hrefBase`, itself resolved relative to the manifest
URL, rather than against the JSON block's location. A `ListingBlock` contains the
same revision, offset, total and an entry array. Empty directories publish one
empty block and one HTML page.

Block filenames contain a revision derived from the public records, URL base,
sort and block size. HTML page filenames remain stable for the configured initial
output filename. No stable-read promise is made across filesystem mutations.
Build publication replaces the output tree and does not retain earlier revision
assets. An asynchronous client must validate the schema and revision, and reload
the manifest on missing/stale blocks; a coherent live-update/cache protocol is
not implemented by these static build contracts. Publication alone does not
configure HTTP caching, authentication or server queries.
