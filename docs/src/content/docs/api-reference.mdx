## Static build

```js
import { generateExplorer } from "@dirwell/core";
import { createPlainTheme } from "@dirwell/theme-plain";
await generateExplorer({ sourceDir: "files", outputDir: "generated", theme: createPlainTheme() });
```

`GenerateOptions` requires source, dedicated output and an explicit theme. Build awaits renderers and metadata, validates assets, then replaces the output tree. It defaults to SSG, relative links and mirrored source files. `outputName` can return a filename or null per directory. `listing` controls HTML pages and data independently. See [configuration](../configuration/) and [deployment](../deployment/).

## Upcoming stable publication controls

These additions are on the development branch for the upcoming stable release; they are not part of the currently published alpha.

`IgnoreFile` is a path or `{ path, baseDir?, optional? }`. `resolveIgnoreFiles` accepts `(files, cwd)` to validate and resolve ordered ignore file paths. `GenerateOptions.ignoreFiles` and live service options default to no ignore discovery. The CLI selects an optional cwd `.gitignore` unless overridden, including with `[]`.

`GenerateOptions.outputPolicy` defaults to `owned`: missing, empty or marked outputs can be published. `replace` permits replacing an unowned nonempty directory. Neither permits a source-containing output or a file/symlink destination. `dryRun` selects and plans without writing output. `generateExplorer` returns a `BuildReport` containing selected paths, directory-page names, theme and replacement scope. Publication keeps a rollback backup until the staged output is installed.

`defineConfig` from `@dirwell/cli` preserves configuration types and rejects unknown nested options before starting either mode. CLI builds accept `--force`/`-f` and `--dry-run`; both modes accept repeatable `--ignore-file` and `--no-ignore`.

## Browser listing loader behavior

`@dirwell/core/client` exports `loadListing` and `parseListingEntries`. The loader fetches coherent public records and retries once when a live revision expires. Private filesystem objects never belong in browser payloads. Data splitting is independent of HTML pagination and row rendering.

## Theme rendering

`ExplorerTheme.render(ThemeContext)` owns a complete document and optional string/byte assets. Context contains private Node-side directory facts, safe link functions, sort settings, optional listing and metadata. Escape untrusted text. Use projected public entries for client data, never absolute paths or raw stat metadata. A theme may add JSON entry data, opt into native pagination and choose whether to generate an archive search index.

## Public annotations and file URL mapping (upcoming stable)

`entryData(entry, context)` is an optional Core build/live-service callback. It receives public logical facts (`id`, `name`, `kind`, `size`, `modifiedAt`, `link`) and `{operation, directoryPath}`; it does not receive private source paths or raw stat records. Return a plain JSON object, synchronously or asynchronously. Values are copied and validated, then exposed as `ListingEntry.data`. This is a public field: publish only information intended for every reader allowed to list that directory.

The callback runs for each selected row, concurrently within a directory, on each build or live listing read. Await all results before rendering, revision calculation or publication. Cache expensive sidecar/remote work in the caller, and keep results deterministic for a coherent live revision. An annotation change affects the listing revision and SSE refresh. This hook changes display data; it does not rename paths, grant access, or expand search scope. Theme-derived `presentation` remains separate.

For static publication, `fileHref(logicalPath)` returns a synchronous HTTP(S), root-relative or relative URL, or `null` to omit the link. It runs once per canonical file path per build and is reused by listing and archive search. Encode each logical path segment before appending it to a CDN URL. Directory links, page/data/assets and unavailable symlink targets retain their existing rules. Combine with `mirror: false` when the files already exist on the host/CDN; otherwise mirroring still copies selected files. The host owns response headers and CDN access control.

```js
await generateExplorer({
  sourceDir: "./files",
  outputDir: "./generated",
  theme: createPlainTheme(),
  mirror: false,
  fileHref: (logicalPath) =>
    "https://cdn.example.com/releases/" + logicalPath.split("/").map(encodeURIComponent).join("/"),
  entryData: (entry) => ({ description: annotations[entry.id]?.description ?? "" }),
});
```

## Direct JavaScript validation (upcoming stable)

Core generation, DirectoryService and Server reject unknown option keys and incorrect value shapes. Diagnostics include the complete option path and a likely correction. Invalid direct options fail before publication writes, directory-service initialization or socket creation. A listing callback is evaluated after directory inspection; its returned plan is checked before output replacement. Custom theme fields remain allowed, while required render/name and known hooks must match their declared contract. Trusted async metadata and annotation callbacks are still awaited.

```js
// Rejected: options.exlcude. Did you mean options.exclude?
await generateExplorer({
  sourceDir: "files",
  outputDir: "generated",
  theme,
  exlcude: ["drafts/**"],
});
// Rejected: mirror must be a boolean.
await generateExplorer({ sourceDir: "files", outputDir: "generated", theme, mirror: "false" });
```

Pass Node-specific `host`/`port` only to `startExplorerServer`; the Fetch handler and Core directory service have separate option contracts. Runtime validation checks configuration and callback results, not side effects performed by trusted callbacks. These checks are not available in the published alpha.
