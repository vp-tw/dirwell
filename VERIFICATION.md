# SDK verification record

The synchronized `@dirwell/*` family is published at `0.0.2`, selected by `latest`. This record distinguishes source/registry qualification from public-page and physical-device evidence. It is not a WCAG, hostile-filesystem or production-capacity claim.

- [Publication controls](https://github.com/vp-tw/dirwell/pull/78): nested CLI validation, ordered ignore files, output ownership/force, canonical containment, recovery/locks and dry run. Current-head checks included installed consumers on six Linux/Windows/macOS ARM64/x64 runners across Node 22.12, 24.1 and 26.
- [Customization](https://github.com/vp-tw/dirwell/pull/79): labels/brand/columns/actions, public annotations, static file mapping, source actions and index controls. 206 Node tests, nine packed consumers, translated desktop/mobile/native paths and paired compiler output passed, followed by 23 exact-head CI checks and deployed guide readback.
- [Browsing continuity](https://github.com/vp-tw/dirwell/pull/80): shared controls, History focus/scroll, failed/complete snapshot recovery, skipped-parent fallback and measured Crosswave windows. 25 Chromium scenarios, 10,000 long rows, unusually tall viewport and all 23 exact-head checks passed. [Benchmark conditions and limits](BENCHMARKS.md) remain workload-specific.
- [Direct configuration](https://github.com/vp-tw/dirwell/pull/81): Core/Server/adapters reject malformed keys/values before initialization/publication and retain trusted callbacks/custom theme fields. 212 Node tests, packed consumers, 21 browser paths and all 23 exact-head CI checks passed; public API/support content was independently read back.
- [Package discovery](https://github.com/vp-tw/dirwell/pull/82): nine isolated README programs with documented root dependencies, minimum Node 22.12 CI, source compiler/PNG/Vite/live paths, matching metadata and desktop/mobile website task paths. All 24 exact-head checks and deployed website readback passed. Local sibling tarball overrides resolved unpublished artifacts; they did not install unused family packages or qualify registry defaults.
- [Private integration and CSP](https://github.com/vp-tw/dirwell/pull/83): anonymous/expired/withdrawn session denial across documents/JSON/assets/ranges/conditionals/SSE, approved bytes, aliases, fresh nonces, actual inline-handler blocking, encoded paths, styles/head and live navigation. Six Ledger/Crosswave cases passed Chromium/Firefox/WebKit; current-head source CI passed. These used synthetic sessions and approved local fixtures.

Optional automated reviewers were unobserved where they did not start. Complete paginated feedback and current-head checks were reconciled after Ready; no silence was treated as a submitted review.

## Shared public listing example

The standalone `examples/shared-cache` application uses published Server/Plain 0.0.2, Hono 4.13.13, its official Node adapter 2.1.5 and node-redis 6.3.0. SDK package payloads and APIs are unchanged. Six example checks cover invalid/corrupt cache data, failed writes, a delayed old fill, concurrent cold misses, two real Node processes sharing Redis, namespace isolation, source updates, normal HTML/file transport, TTL expiry and disconnected-client fallback. The cache is limited to the public root listing API; it does not qualify private listings or cache the explorer, file streams, search or SSE.

A separate agent with no conversation history started from the example catalog, copied the example into a clean temporary directory and installed its locked published dependencies. Following the README, it started two Node processes and an isolated Redis 8 service, observed A miss/B hit with read counts 1/0, added files and invalidated, waited for expiry, stopped/restarted Redis and observed bypass/recovery. It read back the revised text after reporting initial ambiguity about the cached API and dataset identifier. This was an independent agent task trial, not a human usability study; it fetched explorer HTML but did not visually operate the explorer. It removed its own processes, container/network and temporary files.

A second conversation-free agent performed reading/decision tasks and correctly chose static output for a static host, the shared example for public listing reuse, and the private recipe rather than this cache for per-user visibility. Its findings led to explicit theme installation labels and moving documentation-site build instructions out of the user example guide. Desktop (1280 px) and mobile (390 px) Chromium checks verified nine demo links, one local-run link, guide navigation and no horizontal overflow.

The site catalog distinguishes browser previews from local server examples. Only previewable entries enter the static build; the server example links to its guide and source. The site remains statically deployed. Redis installation and commands belong to the standalone example and are absent from SDK dependencies. Two simultaneous misses may still perform two source reads; no distributed lock or production capacity claim is made.

## Support and release boundaries

Keyboard, browser engine, mobile viewport, native no-JavaScript, reduced-motion and simulated standard gamepad paths have bounded automated/browser evidence. Physical iOS and real screen-reader output remain pending qualification; physical controller testing is not a separate gate by user decision. Simulators/viewports and injected input do not become physical-device claims.

Core/Plain stay free of framework, image, font and watcher runtime dependencies. Rich themes load complete directory data despite blocks/windows. Share images support supplied local font coverage alongside the bounded default fonts. Opt-in live archive queries are qualified under explicit scan/concurrency/time budgets; distributed caching remains deferred. Private examples rely on an application-owned current session and approved root, not row-level redaction or an identity provider.
